[CRITICAL-2] HealthLog Stats Calculation Broken
────────────────────────────────────────────────────────────────────────────
Category: Data Model | Module: Logs/Dashboard
Status: UNFIXED

Problem:
  • HealthLog stores meals in nested structure: meals[].calories
  • computeStats() expects this structure but falls back to non-existent top-level fields
  • Dashboard shows avgCalories: 0, avgWater: 0 even with logged meals

Data Structure Mismatch:
  Correct structure:
    { meals: [{ mealType: "breakfast", calories: 500, proteinG: 25 }], waterIntake: 2.5 }
  
  What naive clients send:
    { calories: 500, water: 2.5 }  ← Gets ignored

Reproducible Steps:
  1. Create HealthLog without nested meals structure
  2. GET /api/logs/data/stats
     Response: { avgCalories: 0, avgWater: 0 }  ← Expected: avgCalories: 500+

Impact: Dashboard stats completely non-functional for majority of users

Fix Strategy:
  • Add API validation in logs endpoint to enforce nested structure
  • Document required structure in API spec with examples
  • Create data migration for existing logs with flat structure
  • Add middleware to normalize incoming log data


[CRITICAL-3] Sleep Duration API Confusion
────────────────────────────────────────────────────────────────────────────
Category: API Design | Module: Sleep/Logs
Status: UNFIXED

Problem:
  • Sleep stored in nested structure: sleepEntry.durationMinutes
  • Generic /api/logs endpoint doesn't validate or enforce this
  • Users expect top-level durationMinutes (intuitive but wrong)

Reproducible Steps:
  1. POST /api/logs/2024-07-01
     Body: { "durationMinutes": 480 }
     Result: SILENTLY IGNORED (no error, no data saved)
  
  2. POST /api/sleep
     Body: { "durationMinutes": 480 }
     Result: ✓ Works (correct endpoint)

Impact: Users cannot log sleep through intuitive API path

Fix Strategy:
  • Add validation in logs endpoint to reject top-level sleep fields
  • Return helpful error: "Use POST /api/sleep for sleep data"
  • Document sleep vs logs endpoints clearly
  • Consider consolidated endpoint with smart routing
